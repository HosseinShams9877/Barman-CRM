## ۲. مرزهای هر ماژول

### leads
- **دارد**: کانبان ۵ مرحله‌ای، ویرایش سرنخ، تاریخچه پیگیری، تبدیل به PF
- **ندارد**: مدیریت حساب (→ customers)، ویرایش محصولات (→ admin)
- **وابسته**: customers (حساب)، sales (ساخت PF)، admin (فهرست reasonها، sources)

### sales
- **دارد**: خط لوله سفارش، آیتم‌ها، پرداخت‌ها، چک‌های دریافتی، چاپ پیش‌فاکتور
- **دارد**: نمودار جریان نوار پیشرفت (`flow.html` معادل)
- **ندارد**: حرکت انبار (→ inventory)، کار تولید (→ production)
- **وابسته**: leads، customers، inventory (بررسی رزرو)، finance

### production
- **دارد**: کارهای تولید (PJ)، خطوط تولید (JST/LANES)، تخصیص
- **ندارد**: سفارشات (فقط می‌خواند)، موجودی (حرکت کسر BOM → inventory)
- **وابسته**: sales (خواندن سفارش)، inventory (BOM)

### inventory
- **دارد**: حرکت‌ها (moves)، موجودی محاسبه‌شده، کف اقلیم (min)، هشدار
- **دارد**: کاتالوگ مواد خام (نگارش مشترک با admin)
- **ندارد**: خرید (→ purchasing)
- **وابسته**: admin (materials)، purchasing (ورود کالا)

### purchasing
- **دارد**: درخواست خرید، تأیید، فاکتور، دریافت کالا
- **ندارد**: پرداخت (→ finance)
- **وابسته**: inventory (افزودن موجودی)، finance (پرداخت)

### finance
- **دارد**: وصول/پرداخت، چک‌های صادره، تراکنش‌ها، گزارش مالی
- **ندارد**: محتوای سفارش (فقط خواندن)
- **وابسته**: sales (خواندن PF)، purchasing (خواندن خرید)

### customers
- **دارد**: اشخاص/شرکت‌ها، مخاطبین، تلفن‌ها
- **ندارد**: سرنخ‌ها (→ leads)
- **وابسته**: — (پایه)

### admin
- **دارد**: کاربران، نقش‌ها، تنظیمات، محصولات، فهرست‌ها
- **ندارد**: داده‌های تراکنش‌محور
- **وابسته**: — (پایه)

## ۳. قوانین مرز

۱. **ارتباط از طریق `index.ts`**: هر ماژول فقط API عمومی خود را صادر می‌کند (توابع، تایپ‌ها).
۲. **ممنوعیت ایمپورت متقابل**: `A → B` و `B → A` مجاز نیست — در صورت نیاز، وابستگی مشترک به `core` منتقل می‌شود.
۳. **قرارداد داده**: ماژول‌ها از طریق تایپ‌های `types/` با هم ارتباط دارند، نه از طریق ساختار داخلی.
۴. **shared state**: وضعیت مشترک (مثلاً فهرست سرنخ‌ها) از طریق React Query keys مدیریت می‌شود.
۵. **منطق مشترک** (مثل rnd rounding، normPhone) در `core` — هرگز در دو ماژول کپی نشود.
