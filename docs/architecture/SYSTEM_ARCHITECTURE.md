# SYSTEM_ARCHITECTURE — معماری سیستم هدف

> این سند معماری **پلن** است (فاز صفر: هیچ‌چه پیاده‌سازی نشده). پشته طبق سند راهرسی اجباری است.

## ۱. نمای کلی

```
┌──────────────────────────────────────────────────────────┐
│                 کلاینت (مرورگر، RTL فارسی)                 │
│   Next.js App Router + React + TypeScript strict          │
│   Tailwind + توکن‌های centralized CSS                     │
│   TanStack React Query v5 (QueryClient مرکزی)             │
└───────────────────────┬──────────────────────────────────┘
                        │  JSON/HTTPS
┌───────────────────────▼──────────────────────────────────┐
│              Next.js Route Handlers (thin)                │
│              src/app/api/<module>/route.ts                │
│   احراز هویت نشست (cookie) + مجوز RBAC + Zod             │
└───────┬───────────────────────────────┬──────────────────┘
        │                               │
┌───────▼───────┐              ┌────────▼─────────┐
│ لایه سرویس    │              │  Prisma 6        │
│ src/modules/  │              │  (PostgreSQL)    │
│ <module>/     │              │  توسعه: SQLite   │
└───────────────┘              └──────────────────┘
```

## ۲. لایه‌ها

| لایه | محل | مسئولیت |
|---|---|---|
| رابط کاربری | `src/app/**/page.tsx` + `src/modules/*/components` | نمایش، تعامل، Persian RTL |
| مدیریت وضعیت سرور | `src/modules/*/queries` + `src/core/query` | React Query، کلیدها، invalidation |
| لایه سرویس مشترک | `src/modules/*/services` | فراخوانی fetch، قالب‌بندی درخواست |
| خط مشی کسب‌کار | `src/modules/*/lib` + `src/core/*` | محاسبات، قوانین، تقویم، قالب‌بندی |
| اعتبارسنجی | `src/modules/*/schemas` (Zod) | هم سمت کلاینت هم سرور |
| API | `src/app/api/**/route.ts` | کنترلر نازک: احراز هویت + مجوز + فراخوانی سرویس |
| داده | Prisma schema در `prisma/schema.prisma` | دسترسی به داده، تراکنش‌ها |

## ۳. اصول معماری

۱. **Route Handlers نازک**: هیچ منطق کسب‌کاری در `route.ts` نیست؛ فقط احراز هویت، بررسی مجوز، اعتبارسنجی ورودی با Zod، فراخوانی سرویس و قالب خروجی.
۲. **منطق کسب‌کار در ماژول‌ها**: در `src/modules/<m>/lib` — قابل آزمون و مستقل از HTTP.
۳. **اعتبارسنجی دوگانه**: هر اسکیمای Zod هم در فرم و هم در Route Handler استفاده می‌شود (هرگز فقط کلاینت — درس گرفته‌شده از R-02/R-13).
۴. **مجوز در سرور**: هر Route Handler با `requirePermission(...)` شروع می‌شود (درس از R-02).
۵. **یک موتور تقویم**: فقط `src/core/calendar` (درس از R-16).
۶. **یک منبع توکن رنگ**: `src/styles/globalCss/tokens.css` (درس از R-17).
۷. **یک QueryClient**: در `src/core/query` با کلیدهای مرکزی (نه ad-hoc `useEffect+fetch`).
۸. **Persian-first / RTL-first** و **واکنش‌گرا کامل**.
