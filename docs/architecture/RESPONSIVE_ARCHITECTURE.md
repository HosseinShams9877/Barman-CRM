## ۲. طرح هدف — سیستم breakpoint واحد

| نام | حد | هدف کلاس دستگاه |
|---|---|---|
| `xs` | `< 480px` | گوشی عمودی ( کوچک) |
| `sm` | `480–767px` | گوشی بزرگ / تبلت کوچک |
| `md` | `768–1023px` | تبلت |
| `lg` | `1024–1279px` | لپ‌تاپ |
| `xl` | `≥ 1280px` | دسکتاپ |

قوانین:
۱. **این ۵ نقطه تنها نقاط مجاز هستند** — هیچ عدد_mid دیگری در کد نیست.
۲. ترجیح: container query برای کامپوننت‌های مستقل (کانبان، جدول) —Demo از ۲ مورد استفاده کرده و الگوی خوبی است.
۳. موبایل-اول (mobile-first): استایل پایه برای `xs`، سپس `min-width` برای بزرگ‌ترها.

## ۳. استراتژی جدول‌ها

| عرض | الگو |
|---|---|
| `≥ md` | جدول کامل `.tbl` (مانند Demo) |
| `< md` | **card list**: هر ردیف به کارت تبدیل می‌شود (الگوی موجود در Demo: `.fl-list`, `.ld-tile`) |

قانون: هیچ‌گاه اسکرول افقی برای جداول اصلی استفاده نمی‌شود — card list جایگزین می‌شود. جداول کم‌اهمیت (مثل لاگ) می‌توانند اسکرول افقی داشته باشند.

## ۵. تست واکنش‌گرا — الزامات

طبق سند راهرسی، **فقط عرض‌های واقعی آزمایش‌شده ضبط می‌شوند**.

| ابزار | محدودیت (از محدودیت‌های محیط) |
|---|---|
| Chrome headless `--dump-dom` | حداقل عرض ۵۰۰px (محیط اینجا نمی‌تواند کمتر از ۵۰۰ را رندر کند) |
| مشاهده تصویر | ممکن نیست — verification فقط DOM محتواست |

عرض‌های آزمایشی برنامه‌ریزی‌شده برای Phase 8: ۵۰۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰.
عرض‌های کمتر از ۵۰۰px باید با DevTools شبیه‌سازی شوند و به‌صورت ضمنی بررسی شوند — اما تا زمان آزمایش واقعی، **ادعای تأیید آن‌ها ثبت نمی‌شود**.

## ۶. قوانین طراحی

۱. **RTL-first**: همه چیدمان‌ها از راست شروع می‌شوند؛ breakpoint‌ها برای هر دو جهت یکسان کار می‌کنند.
۲. **touch target**: حداقل ۴۴px در `xs`/`sm`.
۳. **اندازه فونت پایه**: ۱۴px در دسکتاپ، ۱۵–۱۶px در موبایل (جلوگیری از zoom iOS).
۴. **viewport meta**: `width=device-width, initial-scale=1`.
۵. **استفاده از `clamp()`** برای اندازه‌های سیال where منطقی.
۶. **عدم انگشت‌گذاری (no hover-only)**: هر عملکرد مهم با لمس قابل دسترسی باشد.
