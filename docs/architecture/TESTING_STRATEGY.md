# TESTING_STRATEGY — استراتژی آزمون

> طرح (فاز صفر). طبق سند راهرسی: Vitest. Demo در حال حاضر **آزمونی ندارد** — این یک ریسک اصلی است.

## ۱. وضع موجود

- **صفر آزمون خودکار** در Demo (هیچ framework تستی، هیچ فایل spec).
- همه بررسی‌ها دستی در مرورگر — ذهن‌پسند و غیرقابل تکرار.
- قوانین کسب‌کار ضمنی (گردکردن + جبران، رزرو، validDays) فقط در کد موجودند.

## ۲. چارچوب و ابزارها

| ابزار | نقش |
|---|---|
| **Vitest** | آزمون واحد و یکپارچه |
| Vitest + jsdom | آزمون کامپوننت‌های React (سبک) |
| **React Query test utils** | آزمون hookهای query |
| Prisma test DB (SQLite موقت) | آزمون سرویس‌ها + Route Handlers |
| Chrome headless `--dump-dom` | بررسی DOM در زمان توسعه (محدودیت: حداقل ۵۰۰px، بدون تصویر) |

## ۳. هرم آزمون

### ۳.۱ لایه ۱ — واحد (بیشترین حجم)

هدف اصلی: **منطق کسب‌کار** که در Demo پنهان است:

| هدف | محل | نمونه |
|---|---|---|
| موتور تقویم | `core/calendar` | JDN ↔ جلالی، کبیسه‌ها، مرزها |
| گردکردن | `core/formatting` / `sales/lib` | `rnd()` با ۱۰۰٬۰۰۰ و جبران ردیف آخر |
| محاسبه موجودی | `inventory/lib` | onHand/reserved/freeQty، کف (min) |
| پرداخت‌ها و چک‌ها | `finance/lib` | حالت‌های چک (hand/bank/clear/bounce)، sayad |
| اعتبارسنجی | `*/schemas` (Zod) | فرم‌ها، نرمال‌سازی تلفن |
| مجوزها | `core/permissions` | ماتریس نقش × عملیات |
| خط لوله سفارش | `sales/lib` | انتقال‌های مجاز وضعیت |
| BOM و ضایعات | `production/lib` | کسر مواد با درصد ضایعات |

### ۳.۲ لایه ۲ — یکپارچه

- سرویس‌ها با SQLite موقت (یک schema isolate برای هر فایل تست).
- Route Handlers با session ساختگی و نقش‌های مختلف — **تأیید مجوز سرور** (R-02).
- بدنه نامعتبر و PATCH/POST با بدنه بد → خطای Zod.

### ۳.۳ لایه ۳ — رابط کاربری (سبک)

- کامپوننت‌های پایه در `components/ui` (دیالوگ، datepicker جلالی).
- حالت‌های loading/error/empty.
- **بررسی خودکار رنگ hardcoded** (طبق سند راهرسی): یک تست که در `src/` به دنبال الگوهای `#[0-9a-f]{3,8}` می‌گردد و شکست می‌خورد (استثنا: فایل‌های توکن).

## ۴. پوشش هدف

| لایه | هدف |
|---|---|
| منطق کسب‌کار (`core/*`، `*/lib`) | ≥ ۹۰٪ |
| ماژول‌ها (services) | ≥ ۸۰٪ |
| کامپوننت‌ها | ≥ ۶۰٪ (ارزش کمتر، هزینه بیشتر) |
| API routes | پوشش مجوز ۱۰۰٪ (هر مسیر حداقل یک تست 403) |

## ۵. داده‌های آزمون

- اسکریپت seed از داده واقعی Demo (۱۴۸ سند نمونه) — هرچند داده حساس نیست، فقط در محیط توسعه/آزمون استفاده می‌شود.
- فیکسرها (fixtures) برای هر موجودیت: account، lead، order, buy، job, move, txn.
- حالت‌های حاشیه: تاریخ‌های کبیسه، چک‌های برگشتی، موجودی صفر، رزرو بیشتر از موجودی.

## ۶. اجرا

- `vitest run` در CI (هر کامیت).
- `vitest watch` در توسعه.
- گزارش پوشش با `--coverage`.

## ۷. آنچه آزمون نمی‌پوشاند (محدودیت‌های صادقانه)

- **رفتار بصری** — این محیط نمی‌تواند تصاویر را ببیند؛ بررسی بصری دستی باقی می‌ماند.
- **عرض‌های زیر ۵۰۰px** — محیط حداقل ۵۰۰px را رندر می‌کند (See `RESPONSIVE_ARCHITECTURE.md` §۵).
- **همزمانی چندکاربری واقعی** — نیاز به محیط staging دارد.
