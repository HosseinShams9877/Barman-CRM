# MODULE_CATALOG — فهرست ماژول‌های کسب‌کار (مطابق با واقعیت Demo)

> فهرست ماژول‌ها بر اساس بازرسی **تکمیل‌شده** همه صفحات Demo تهیه شده است (طبق الزام: «فهرست ماژول‌های کسب‌کار را پس از بازرسی کامل به Demo واقعی تطبیق دهید»).
> هر ماژول به یک ماژول هدف `src/modules/<name>/` در معماری هدف نگاشت می‌شود. این فهرست صرفاً برنامه‌ریزی است و هیچ پیاده‌سازی انجام نشده است.

## ۴. نگاشت مرزها

هر ماژول در معماری هدف این ساختار را خواهد داشت (طبق سند راهبری):

```
src/modules/<module>/
├── components/   — UI اختصاصی ماژول
├── hooks/        — hookهای React Query اختصاصی
├── lib/          — منطق ناب ماژول (محاسبات، تبدیل‌ها)
├── services/     — فراخوانی API
├── types/        — تایپ‌های اختصاصی
├── schemas/      — اسکیماهای Zod اعتبارسنجی
├── constants/    — ثابت‌های ماژول (مثلاً CST، KIND، JST)
├── queries/      — کلیدهای پرس‌وجو و تعریف‌های مرکزی
└── index.ts      —_API عمومی ماژول (مرز ورودی)
```

**قاعده مرز**: هیچ ماژولی نباید مستقیماً از `components/` ماژول دیگر ایمپورت کند — فقط از طریق `index.ts` و فقط types/توابع ناب. منطق مشترک باید به `src/core/` منتقل شود.

## ۵. هسته مشترک (`src/core/`)

| پوشه | مسئولیت | معادل در Demo |
|---|---|---|

| `query` | QueryClient مرکزی، کلیدها، invalidation | (در Demo: snapshot polling) |

## ۶. یافته‌های بازرسی مؤثر بر ماژول‌بندی

- **`fin-core.js` (۷۶ خط) وظایف دو حوزه را در هم آمیخته است**: وضعیت خرید (نوع `purchasing`) و رسید/انبار (نوع `inventory`) و جریان نقدی (نوع `finance`). در معماری هدف این سه باید جدا شوند.
- **`admin.js` (۱۸۴ خط) سه حوزه مختلف را در یک فایل دارد**: کاتالوگ محصول/ماده و BOM (نوع `admin` یا `catalog`)، کاربران/نقش‌ها (نوع `admin`) و فهرست‌ها/تنظیمات (نوع `admin`).
- **`order.js` بزرگ‌ترین صفحه است (۷۷۸ خط) و خط لوله ۱۱ مرحله‌ای + مالیات + رزرو + چاپ را در خود دارد**. شکستن آن به کامپوننت‌های مرحله‌ای ضروری است.
- **`customer.html` کاملاً مستقل و بدون احراز هویت است**. در معماری هدف این صفحه باید با مسیر امن `_layout` بازنویسی شود (یا حداقل با احراز هویت توکنی کوتاه‌مدت).
- **پنج رنگ/وضعیت مختلف برای فاز سفارش در سه صفحه ناهماهنگ است** (`home.js` ۴ فاز، `flow.js` ۵ فاز، `PHC` در `order.js`) — ماژول `sales` باید یک منبع واحد برای فازها داشته باشد.
