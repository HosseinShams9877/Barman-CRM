# PHASE 01 — پایه و ابزار (Foundation & Tooling)

> این فاز اسکلت پروژه جدید را می‌سازد: پروژه Next.js، TypeScript strict، توکن‌های CSS، لایه `src/core/`، تنظیمات آزمون و RTL. **هیچ منطق کسب‌کاری در این فاز پیاده‌سازی نمی‌شود.**

---

## ۱. هدف فاز

ایجاد پایه قابل اتکای پروژه بر اساس مجموعه‌تکنولوژی اجباری سند راهبری، به‌گونه‌ای که فازهای بعدی فقط منطق کسب‌کار را اضافه کنند. خروجی نهایی فاز: پروژه‌ای که build می‌شود، در ۵ breakpoint بررسی شده، توکن‌های CSS متمرکز در ۶ فایل دارد، و یک آزمون نمونه سبز است.

## ۲. پیش‌نیازها و وابستگی‌ها

- وابسته به **فاز ۰** (مستندات، تصمیمات تأییدشده).
- تأییدهای لازم قبل از شروع: D-01 (استراتژی احراز هویت — فقط برای انتخاب مسیر فاز ۲، اما باید در پایان فاز ۱ نهایی شده باشد)، D-05 (روش بازسازی CSS به‌جای مهاجرت)، Q-09 (پالت رنگی مراحل خط لوله).
- Demo به‌عنوان مرجع بازرسی استفاده می‌شود؛ هیچ فایلی از آن تغییری نمی‌کند.

## ۳. دامنه کارها

۱. ایجاد پروژه Next.js App Router با TypeScript strict.
۲. پیکربندی Tailwind با نگاشت توکن‌های CSS به مقادیر Tailwind (هیچ رنگ hardcoded در config).
۳. ایجاد `src/styles/globalCss/` با ۶ فایل: `tokens.css`، `themes.css`، `typography.css`، `layout.css`، `utilities.css`، `index.css` و ورودی `src/app/globals.css` که فقط `@import` دارد.
۴. ایجاد ساختار پوشه‌ها: `src/modules/`، `src/core/` (۱۳ پوشه: auth، permissions، database، api، calendar، query، validation، errors، formatting، localization، logging، utils)، `src/components/{ui,shared,layout,feedback}` هر کدام با `index.ts` عمومی (barrel) برای خروجی‌های نام‌گذاری‌شده.
۵. بارگذاری فونت Vazirmatn (self-hosted با woff2، معادل Demo در `app/fonts/`) و تنظیم `lang="fa"` و `dir="rtl"` در root layout.
۶. اسکلت layout: `AppShell`، `Sidebar`، `Navbar` (دارای placeholder برای نقش کاربر — بدون احراز هویت واقعی).
۷. تنظیم Vitest با محیط jsdom + یک آزمون نمونه.
۸. اسکریپت تست خودکار «رنگ hardcoded» (اسکن هگزادسیمال/rgb خارج از `tokens.css`/`themes.css`) برای CI.
۹. پیکربندی ESLint + Prettier ( strict، allowed-imports برای محدود کردن وابستگی بین ماژول‌ها).

## ۱۰. رابط کاربری (کامپوننت‌ها)

- `AppShell` با Sidebar قابل جمع‌شدن زیر `md` و Navbar با هدر ساده.
- آیتم‌های منو: خانه، سرنخ‌ها، مشتریان، سفارش‌ها، تولید، انبار، خرید، مالی، مدیریت — همه به‌صورت placeholder غیرفعال (با tooltip «در فاز بعدی»).

## ۱۱. واکنش‌گرایی و breakpointها

- سیستم ۵ نقطه‌ای: `xs < 480`، `sm 480–767`، `md 768–1023`، `lg 1024–1279`، `xl ≥ 1280`.
- Sidebar زیر `md` به دکمه همبرگری تبدیل می‌شود (drawer).
- عرض‌های آزمایش واقعی برنامه‌ریزی‌شده: **۵۰۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰** (با Chrome headless و `--dump-dom` — فقط این عرض‌ها ضبط می‌شوند؛ ادعای عرض‌های آزمایش‌نشده ممنوع است).
- محدودیت محیط: حداقل عرض قابل آزمایش ۵۰۰px است؛ زیر این عرض ادعایی داده نمی‌شود.

## ۱۲. آزمون‌ها

- تنظیم Vitest + jsdom + environment coverage.
- یک آزمون نمونه (مثلاً تبدیل ارقام فارسی در آینده؛ فعلاً یک unit ساده روی یک تابع کمکی مثل `cn` کلاس‌ها) برای اثبات زنجیره.
- اسکریپت `check-hardcoded-colors.mjs` در CI اجرا می‌شود — هر رنگ هگز خارج از فایل‌های توکن، CI را قرمز می‌کند.
- پوشش مورد انتظار این فاز: فقط زیرساخت (بدون هدف درصد خاص).

## دروازه خروج هدفمند (Objective Exit Gate)

فاز ۱ فقط زمانی بسته می‌شود که **همه** موارد زیر عیناًبررسی شده باشند:

1. `next build` بدون خطا انجام می‌شود و خروجی production تولید می‌گردد.
2. شش فایل `globalCss/` وجود دارند و `globals.css` هیچ قانون CSS مستقیمی ندارد (فقط `@import`).
3. اسکریپت رنگ hardcoded در پروژه جدید صفر مورد گزارش می‌کند.
4. صفحه اول در عرض‌های ۵۰۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰ با Chrome headless بررسی شده و بدون اسکرول افقی است (عرض‌های واقعی ضبط شده).
5. `dir="rtl"` و `lang="fa"` در root خروجی DOM تایید شده‌اند.
6. `vitest run` سبز است و حداقل یک آزمون وجود دارد.
7. هیچ فایل Demo تغییری نکرده است (diff خالی).
8. D-01، D-05، Q-09 پاسخ داده شده‌اند.
