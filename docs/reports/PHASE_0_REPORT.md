## ۴. نمای کلی برنامه Demo

یک CRM یا بازرگانی فارسی (RTL) تک‌شرکتی، مبتنی بر plain HTML/JS + Node سرور، با ذخیره‌سازی فایل-محور (JSON) و بدون پایگاه داده رابطه‌ای. برنامه در حال تولید است (غیر پایدار) و ۷ نقش کاربری دارد: admin، manager، sales، ops، production، warehouse، finance.

**نقاط قوت:** پوشش کامل فرایند از سرنخ تا تحویل و مالی؛ قوانین کسب‌کار غنی و واقعی؛ داده نمونه کافی برای مهاجرت.

**نقاط ضعف (پایه فنی):** بدون پایگاه داده (شخص ۲۳ سند در ۲۳ فایل)، بدون سیستم آزمون، منطق در رشته‌های HTML جاسازی شده، ۶۷٪ CSS مرده، ۱۲۴ نقطه breakpoint پراکنده، سه پالت رنگی متفاوت برای مراحل فروش، مجوزها فقط در کلاینت، و دو قالب تاریخ همزمان.

### ۵.۲ قراردادهای کلیدی

## ۶. قوانین کسب‌کار بحرانی (بدون اختراع)

این قوانین مستقیماً از Demo استخراج شده‌اند و در معماری هدف **عیناً** حفظ می‌شوند:

۱. **خط لوله سفارش ۱۱ مرحله‌ای** — بدون اعتبارسنجی ترتیب (R-03/Q-03).
۲. **`moves` منبع حقیقت موجودی** — هیچ فیلد موجودی ذخیره نمی‌شود.
۳. **BOM با پیش‌نمایش زنده** در دیالوگ ایجاد کار تولید.
۴. **QC با قانون `good + waste ≤ qty`**.
۵. **جریان خرید `req → ok → fin → recv`** با چک‌های `issued|paid`.
۶. **`txns` با ۸ نوع هزینه ثابت** + دریافت متفرقه.
۷. **`settings`**: `vat`، `validDays`، `discountCap` هر نقش.
۸. **قانون `noMoney`** — نقش‌های production/warehouse مبالغ را نمی‌بینند.
۹. **`discountCap` پیش‌فرض ۰** — معنای آن باز (Q-02).
۱۰. **رزرو `data-daccept`** بدون بررسی موجودی (Q-04).

## ۱۵. خط‌مشی تقویم و تاریخ

- تاریخ محض: `YYYY/MM/DD` ASCII در ذخیره‌سازی و قراردادها.
- نمایش: فارسی با ارقام فارسی.
- لحظه (timestamp): UTC ms.
- JDN فقط به‌عنوان نمایش محاسبات داخلی (مثلاً bucketing ماهانه).
- یک موتور واحد در `core/calendar` (مبتنی بر JDF) — بدون `Intl`.

## ۱۶. خط‌مشی مجوزها

- منبع حقیقت: سرور (`requirePermission`).
- پنهان‌سازی دکمه در UI فقط تجربه کاربری است — مجوز نیست.
- ماتریس ۷ نقش × مجوز کاملاً از Demo بازسازی شده (در `USER_ROLES_AND_PERMISSIONS.md`).
- قانون `noMoney`: نقش‌های production/warehouse مبالغ را در پاسخ API دریافت نمی‌کنند (فیلتر سرور).

## ۱۷. خط‌مشی رابط کاربری

- فارسی‌اول و RTL‌اول (`lang="fa"`, `dir="rtl"`).
- ۵ breakpoint: xs <480، sm 480–767، md 768–1023، lg 1024–1279، xl ≥1280.
- رنگ‌ها فقط از توکن معنایی — رنگ hardcoded ممنوع (با تست خودکار بررسی می‌شود).
- فونت: Vazirmatn self-hosted (woff2).

## ۱۸. خط‌مشی آزمون

- هر فاز آزمون‌های خود را همراه با پیاده‌سازی تحویل می‌دهد (نه در انتها).
- پوشش هدف: ≥ ۹۰٪ روی منطق کسب‌کار (فاز ۸).
